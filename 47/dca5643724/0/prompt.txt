## Exploration outcome (for the PR description)

**A debug-build "sound requests published with no consumer" warning cannot be implemented cheaply or honestly — the issue's hypothesis is confirmed.** Verified against the exact pinned version, DefaultEcs `0.18.0-beta01` (`MonoDreams/MonoDreams.csproj:143`), read from `~/.nuget/packages/defaultecs/0.18.0-beta01/`. Its entire public pub/sub surface is `World.Publish&lt;T&gt;(in T)` / `World.Subscribe&lt;T&gt;(MessageHandler&lt;T&gt;)`, the same two members on `IPublisher`, and the attribute-driven `IPublisherExtension.Subscribe` helpers — there is no subscriber count, no has-listeners query, and no way to enumerate subscriptions. Cross-checked two ways: the package's `DefaultEcs.xml` documents no such member, and a dump of the assembly's `#Strings` heap (which carries private names too) contains no symbol resembling `SubscriberCount` / `HasSubscribers` / `ListenerCount`; the only `GetSubscriptions` symbols are compiler-generated local functions (`g__GetSubscriptions|NN_0`) inside `World.SubscribeEntityComponentRemoved` / `SubscribeWorldComponentRemoved` / `AResourceManager.Manage`, and the subscription lists are private fields (`_subscriptions`, `_nonReactSubscriptions`) of an undocumented internal `Publisher&lt;T&gt;`.

Beyond the missing API, the module has no seam to check from. The engine does not own the publish call — game code writes `world.Publish(new PlaySoundRequest(...))` directly (`AudioDemoScreen.cs:197`), so counting consumers would require routing one-shots through an engine-owned wrapper, i.e. a second way to play a sound, which the module's own "exactly one idiomatic way per use case" premise forbids. The three remaining ideas are all hacks the issue rejects: reflection into `Publisher&lt;T&gt;`'s private fields (brittle across a *beta* whose release notes already record renamed subscribe members); a module-registered sentinel subscriber (circular — the only module-owned object is `AudioSystem` itself, the very thing being forgotten); and a composition-time assertion (the engine has no pipeline-validation hook — screens build plain `SequentialSystem`s, and `EditorPipelineRegistrar` is demo/editor-only — plus CORE_TENETS §2 puts pipeline assembly in the screen, not the system). There is also no `#if DEBUG` precedent anywhere under `MonoDreams/`. **Conclusion: no runtime tripwire; the premise is the guard.** That conclusion is folded into the premise text itself.
