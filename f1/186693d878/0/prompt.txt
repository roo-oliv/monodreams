`implement` executa um plano aprovado até virar um Pull Request aberto, e então encadeia o `/review-fix-loop`. A implementação roda dentro de um **Workflow** (`~/.claude/workflows/implement.js`) — esta invocação de skill é o opt-in explícito do usuário para a orquestração multi-agente, incluindo a autorização expressa para os agentes do workflow **commitarem e darem push na branch de trabalho** (somente nela; nunca em `main`, nunca force).

Arquitetura de contexto: **waves + ledger**. O script divide o plano em ondas; cada onda é um agente *fresco* que lê o plano + o ledger de progresso, implementa só a sua fatia, verifica, commita, dá push e atualiza o ledger. Nenhum agente acumula contexto além da própria onda — esse é o substituto do `/compact` (não invocável dentro de agentes de workflow) — e um crash é retomável a partir do ledger + branch.

## Contrato do workflow (o que `review-fix-loop.js` garante)

A economia de rounds vem da auditoria do PR #1065 (10 rounds, 36 B/H): 93% dos B/H pós-round-1 **já estavam visíveis** a rounds anteriores (satisficing — cada especialista acha 1 defeito por superfície e segue), e só 2/28 foram regressão de fix (ambas pegas no round seguinte). Por isso o loop é **largura uma vez, profundidade depois**: re-varrer tudo a cada round paga por cobertura que já existe e não compra profundidade.

- **Classify** (round 1): deep se contrato deep-plan na branch, OU domínio money + mudança de lifecycle/fluxo, OU diff grande/delicado (julgamento do agente); senão standard. `modeHint` força.
- **Review — round 1 e gate (largura)**:
  - *standard* — 1 agente espelhando o prompt da GitHub Action de code review da Anthropic (`pr-review-comprehensive`), spec em `~/.claude/skills/review-fix-loop/agents/standard-review.md`, todos os rounds (PRs simples não pagam o aparato deep).
  - *deep* — fan-out das **8 lentes** do deep-review do repo (`.claude/skills/deep-review/agents/0X-*.md`: 5 de domínio + quantia-derivada, espaço-negativo, contrato×código) + consolidador (`99-consolidate.md` — demoção de B/H só com evidência lida no código; preenche `surface` por B/H).
  - Ambos recebem o **plan-contract da branch como spec atual** (fixes de rounds anteriores atualizam nele a semântica que mintaram) — divergência código↔contrato e quantia derivada sem dimension row são findings, o que impede o reviewer de re-derivar semântica já decidida.
- **Enumerate (todo round deep com B/H)**: para cada superfície quente (agrupamento por `surface`, cap `maxEnumSurfaces` default 6, Blockers primeiro), um enumerador (`95-enumerate.md`) **exaure as facetas da superfície no mesmo round** — writers cross-domain, complemento de escopo, relógio, pernas de fórmula, janelas de crash — com evidência file:line por faceta e veredito `dry`. É o antídoto do padrão 1-faceta-por-round (cluster `paidOrig`: 8 B/H em 8 rounds numa query de ~30 linhas).
- **Review — rounds 2+ (profundidade)**: em vez de novo fan-out pleno: (1) **validador bounded** julga adversarialmente cada fix alegado pelo fixer do round anterior (escopo fechado nos ids; `stillOpen` re-entra); (2) **reviewer de fix-diff** revisa só o delta dos commits do fixer (pega fix-introduced com latência zero); (3) **re-enumeração** das superfícies dos B/H recém-fixados (o fix estreitou a superfície — é quando a próxima camada fica visível).
- **Conciliate**: um agente funde o review fresco com **tudo que já está postado no PR** (reviews/comentários humanos, bots, rounds anteriores deste loop), dedupa, reavalia findings que o fixer contestou com argumento (não re-levanta sem contra-argumento novo), re-precifica Mediums estagnados (idade no prompt), e **posta o review consolidado como comentário no PR** (`gh pr comment` — a API do GitHub não aceita `gh pr review` no próprio PR) com marcador HTML de round/SHA para idempotência. Espaço nunca corta B/H/Medium — só Lows, registrados em `droppedForSpace`.
- **Fix**: agente fixer endereça Blockers+Highs, **Mediums envelhecidos (≥2 rounds na fila — atribuídos, não opcionais)** e Mediums oportunísticos nos mesmos arquivos: implementa, roda verify incremental (sempre com os ArchitectureTests dos módulos tocados), commita, pusha, **atualiza a descrição do PR** (regra de sync de git-conventions) e **responde no PR** quando decide divergir de um finding, com o porquê. Divergências ficam registradas para o conciliador do round seguinte. Fix que muda **predicado, janela temporal, fórmula ou semântica de dinheiro** atualiza o plan-contract da branch + a premissa em `docs/{domain}/premises.md` **no mesmo commit** (strike, don't append) — é o que quebra o loop generativo em que cada round ataca a resolução do anterior (cluster `paidOrig` do PR #1065). **Divergência ratificada** (pelo usuário ou por contestação aceita) também vira amendment no contrato — ratificação que só existe em comentário de PR é re-minerada por todo reviewer fresco.
- **Terminação por exaustão**: clean exige 0 High/Blocker **num round de largura** (round 1 ou gate) **com enumeração seca**. Um round de profundidade que zera H/B apenas agenda o **gate fresh-eyes** (fan-out pleno) no round seguinte — quiet não é exausto; a curva first-seen do #1065 estreou 7 B/H no round 4. O gate ganha +1 round além do cap (uma vez) se necessário. Confirmada a exaustão → **uma última rodada de fix** para os Medium/Low pendentes (com `/verify` completo antes do push final) e **nenhum review novo depois dela**.
